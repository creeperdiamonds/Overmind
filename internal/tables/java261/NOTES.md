# java261

Java 26.1 (protocol 775) lookups. Data in `data/*.gz` and `testdata/*.json` is generated by `go run ./tools/gentables -data <minecraft-data checkout>` from PrismarineJS minecraft-data (commit in the first line of every data file). Never edit by hand; rerun the tool.

- `JavaState(runtimeID)`: Java block state ID for a Dragonfly runtime ID. **It does not finalize the registry: register every block (Dragonfly's, worldgen's snow_layer and seagrass, anything else) and finalize `world.DefaultBlockRegistry` first, or the first call panics with a clear message.** The table is built on the first call: a flat `[]uint16`, about 50 KB.
- Resolution order per state: (1) exact mapping with every property known; (2) the mapped state of the same block sharing the most property values, unless none is shared or the best ties span several Java blocks, then (3) the Java default state of that block; (4) stone, only when Java has no such block. A state carrying properties the mapping lacks is mapped but counted as a fallback. `Stats` counts them; one log line per block name that needed 2 to 4.
- State ID rule: `min state + mixed-radix index of the property values`, last property fastest; bools list `true` first. Applied by the generator, so the runtime only looks up.
- Bedrock property values are matched as the mapping writes them: sorted by name, bools as 0/1. Properties the mapping data does not know are ignored when matching (Dragonfly is newer than the pinned Bedrock data), except `minecraft:corner`, which the generator adds for stairs because the pinned data maps every stair to shape outer_right, and the connections Dragonfly 0.11.6 keeps for Bedrock 1.26 (`minecraft:connection_*` of fences, panes, bars, fire and chorus plants, `redstone_*` of wire), which `newerProperties` sets on the Java state as the Java property of the same meaning (Java batch C).
- `Property(state, name)`, `WithProperty(state, name, value)`, `BlockName(state)`: read and set one property of a Java state, from `data/properties.gz` (every Java block with properties, in state order, values in order, bools `true,false`). `TestPropertiesMatchStateRule` checks every value of every property against the state rule worked out separately.
- `JavaItem` / `BedrockItem`: by item name and meta. Beds and banners map per colour by meta (banner meta is inverted); potions, splash and lingering potions, goat horns, suspicious stew and firework stars give the one Java item for any meta (Java holds the variant as components); an arrow with a meta is a tipped arrow; any other name with a meta gives ok=false. `unknown` and legacy `item.*` names are not mapped. The reverse gives the Bedrock name equal to the Java name, never lit_, standing_, wall_ or double slab names. Block items named differently in Java (snow_layer, snow) come from the block mapping.
- `JavaBiome`, `PacketID`: -1 when unknown. `Registries()` is built per call, in login-packet order.
- Stone is left for blocks Java does not have (wool and concrete stairs and slabs, sulfur, cinnabar, poplar, frames): about 2861 of 15313 typed states in 152 names. See `TestMappedShare`.
- `Tags()`: tag names and registry IDs for the registries the client gets tags for. Built per call. **Blocks, items, fluids and entity types** (`data/tags.gz`) come from azalea-rs/azalea's azalea-registry (MIT) at its 26.1 commit `eeaf1435`, with block, item and entity type IDs from minecraft-data and fluid IDs in azalea's order; azalea's Rust names lose the slash of `mineable/` and `enchantable/`, which is put back; built with `go run ./tools/gentables -data <minecraft-data> -azalea <azalea-registry/src>`. **Timelines, damage types and enchantments** are written by hand in `handtags.go` (ruling 18), copied from minecraft.wiki's tag pages as they stood for 26.1: "Timeline tag (Java Edition)" oldid=3839231 (the same lists as oldid=3310207), "Damage type tag (Java Edition)" oldid=3498996, "Enchantment tag (Java Edition)" oldid=3502711 (the last revisions before any 26.2 snapshot edit; later ones add 26.2 and 26.3 damage types such as `sulfur_cube_hot`). Entry names become IDs by their place in minecraft-data's registry list (`Registries`), a `#tag` in a list is folded in, and a name 26.1's registry lacks panics (`TestHandTags`). The experimental `trades/*` enchantment tags are left out. **No open source has tags for the other registries** (game events, potions, points of interest, instruments, banner patterns, paintings, dialogs, biomes); none are sent, so a client finds them empty.
- `ComponentType(name)`: the ID an item component type has in an item slot (`damage`, `custom_name`), from protocol.json's `SlotComponentType` mapper (`data/components.gz`), -1 when unknown.
- `EntityType(name)`: Java entity type ID, -1 when unknown. `MetadataIndex(entity, key)`: the index of an entity's metadata key, in the order entities.json's `metadataKeys` lists them (`data/metadata.gz`), -1 when unknown; `MetadataType(name)`: a metadata value type's ID, from protocol.json's `entityMetadataEntry` type mapper. `PacketName(state, direction, id)`: the reverse of `PacketID`, "" when there is no such packet.
- `JavaItemID(name)`: a Java item's ID by its Java name (`data/javaitems.gz`, minecraft-data's pc items.json), -1 when unknown.
- `MenuType(name)`, `BlockEntityType(name)`: IDs in the static `minecraft:menu` and `minecraft:block_entity_type` registries (`data/static.gz`), from azalea's registry enums at its 26.1 commit (its `registry!` macro numbers entries in order); the menus agree with minecraft.wiki's Inventory page (oldid=3201379). minecraft-data lists neither. -1 when unknown.
- `CraftingRecipes()`, `Craft(grid, size)`: Java's shaped and shapeless crafting recipes (`data/recipes.gz`): minecraft-data's 26.1 recipes.json, its one-item-at-a-time variants of a recipe merged into one recipe whose cells take each item listed, plus `tools/gentables/corrections.go`, which adds what minecraft-data leaves out (planks from wood and stripped logs, re-dyeing from any colour, pumpkin pie from any egg, fire charges from charcoal), each cited to a minecraft.wiki oldid. Checked outside the repo against the 26.1 data generator's recipes: every result accepts the same grids. Special recipes the game works out in code are not included. `Craft` matches a shaped recipe anywhere in the grid and mirrored left to right (minecraft.wiki "Crafting" oldid=3870665), a shapeless one in any cells. `CraftRemainder(item)`: what an item leaves in the grid when crafted with.
- `DimensionType(name)`: a dimension type's height and sky light (minecraft-data's loginPacket.json) and sea level, **written by hand**, since no open source gives a dimension's own (minecraft-data's captured world is flat): the Overworld 63 from minecraft.wiki "Terrain features" oldid=3873202 (where "Sea level" oldid=3569134 redirects: "Air on altitude Y=63 and lower is replaced by water"); the Nether 31 from the same page's "a lava sea forms below Y=31", its one figure for the Nether, taken as the sea level as 63 is the Overworld's; the End 0, our own choice: the End has no sea of water or lava, so its lowest Y (min_y 0), with nothing below sea level.
